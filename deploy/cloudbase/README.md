## 实际部署与数据

`functions/werewolf` 是容器服务源目录，沿用准备阶段的文件夹名称，实际部署方式为 CloudBase 云托管容器。`main.py` 将原游戏挂到 `/game/`，保留原规则引擎、所有剧本、机器人、房间 WebSocket、开场、大厅、对局界面和语音信令。原电脑项目未修改。

云托管服务 `werewolf` 使用 0.25 核 CPU、0.5 GiB 内存，最小实例 0、最大实例 1，端口 9000。当前版本 `004` 正常运行并接收 100% 新流量，旧版本流量为 0。`PUBLIC_ORIGIN` 为上方网站根地址，HTTP 网关 `/` 指向静态托管，`/game` 指向云托管并保留路径。健康检查为 `/healthz`。

静态托管共上传并核对 529 个文件，包括本地化字体、Three.js、OGL、首屏模型、背景视频，以及 **56 首用户提供的完整 MP3、7 段原视频**。原音视频总计 1,995,894,574 字节，准备时 SHA256 与原文件一致，没有转码或压缩。MP3 歌单沿用 `assets/music/`，国内部署入口映射到实际托管目录 `assets/audio/`。

当前默认入口对带 Range 的测试请求返回完整文件 `200`，未返回 `206`；歌曲实际播放、拖动到 65 秒后继续播放均正常。大视频仍可能需要较多缓冲时间，未将上传成功等同于所有手机的视频拖动性能已验收。

验收记录保存在本机 `.sites-runtime/qa`；腾讯云授权凭据也仅在忽略的本机运行目录内，不能加入 Git 仓库。

目前没有两台分别使用国内手机流量、不同运营商的实机测试，不能声称所有国内网络均已实测。网页有声自动播放遵循浏览器策略，首次访问可能需要一次点击，用户后续选择会保存在自己的浏览器中。

游戏房间保存于容器内存；刷新和短时掉线能恢复席位，但容器重启会丢失正在进行的对局。最小实例为 0，空闲后的第一次连接可能需要等待冷启动。

原版语音使用 WebRTC，已加入免费公开 STUN，未购买 TURN 中继。房间操作通过云端 WebSocket，不依赖同一 Wi-Fi；跨运营商语音是否能直连仍需实测，不能保证所有网络组合的语音连通。

## 本机部署脚本

`scripts/prepare-domestic-site.mjs` 准备国内静态副本，`scripts/prepare-cloudbase-game.mjs` 从原项目生成容器源副本。`scripts/deploy-cloudbase-game.cjs` 在确认仍为免费套餐且未开启超额付费后提交部署。它从本机官方 CLI 登录配置读取临时凭据，不含硬编码密钥。

前端 PWA service worker 仅控制 `/game/`，也仅清理本游戏缓存，不会接管个站或删除另一个网站的缓存。
